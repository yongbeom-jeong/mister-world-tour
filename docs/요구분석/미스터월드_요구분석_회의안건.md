## 회의에서 유지할 기존 기준

- 고객 문서 원문은 신청 인원 **3명 이상** 출발 확정. 허니문 예외는 아래 사용자 해석 제안으로 구분.
- 고객 문서의 허니문·효도 **그랜드 이상** 초기 선택 제한.
- 고객 문서의 호텔·교통·식사 변경 및 음료 추가. 클래식 트레킹에 고급 식사·샴페인 조합 허용.
- 기존 계획서의 **동일 상품·동일 출발일·전체 신청 여행자 수** 집계.
- 기존 계획서의 **최근 3년 이내 여행 3회 이상 완료** 단골 판정.
- 기존 계획서의 상품 등록·수정, 기념품 입고 수량 저장, 역할별 기능 접근, 음성 조회·선택.
- 기존 계획서의 연동 실패 기록·재시도 방향. 상세 방식은 회의 결정 대상.

계획서의 조건은 기존 팀 결정으로 유지하며 고객이 직접 제시한 요구와 출처를 구분한다.

**허니문 사용자 해석 제안(2026-10-03):** 허니문은 정확히 2명이 떠나는 전용 여행으로 공동 모집·3명 조건에서 제외하고, 효도·골프·트레킹에 3명 이상 모집을 적용하자는 안이다. 과제 안내에는 예외가 명시되지 않았으므로 Q04에서 원문 차이와 팀 합의 여부를 검토한다. 전용 여행의 신청 단위·출발 확정 시점·문자 시점도 남긴다. Q04는 종료하지 않는다.

## 모델링 확인과 분담 제안

다음은 팀원 문서의 장점을 반영한 모델링 초안이다. 회의에서 수용·수정 여부를 확인하고 전체 그림과 설명에 함께 반영한다.

- **8개 목표:** UC01 회원가입, UC02 로그인, UC03 이전 여행 이력 확인, UC04 여행 상품 선택 및 구성, UC05 여행 신청, UC06 상품 등록, UC07 상품 수정, UC08 기념품 입고. 옵션 변경은 UC04에 포함하되 선택사항으로 둔다.
- **액터 일반화:** 고객·직원의 공통 가입·로그인을 ‘사용자’ 액터로 묶고 고객·직원을 그 특수화로 표현하는 안. 외부 음성인식·문자 서비스는 지원 액터 후보다.
- **확장 관계:** UC03이 UC02를 `extend`하는 안. 확장 지점은 **고객 인증 성공 후**, 조건은 **고객 역할로 인증 성공**이다. 이력 존재 여부를 조건으로 삼지 않으며 이력이 없어도 조회 흐름은 실행한다. 빈 결과 표현은 Q09에서 합의한다. 직원 로그인은 이력 조회 없이 완료된다.
- **포함 관계:** 현재 8개 목표에는 별도 `include`를 두지 않는 안. 로그인·이전 선택을 사전조건으로 참조하며 공통 동작을 실제로 분리할 필요가 생기면 재검토한다.

설명서·시나리오 작성 담당은 사용자와 논의한 아래 안을 제안한다. 최종 팀 배정은 회의에서 확인한다.

| 담당 제안 | 작성할 UC | 공동 검토할 부분 |
|---|---|---|
| 손경준 — 데이터베이스 | UC01·UC02·UC03·UC06·UC07·UC08 | 계정·역할, 이력의 출처·정렬, 상품 필드/수정 영향, 입고 정책 |
| 김규태 — 백엔드 | UC04·UC05 | 옵션·가격/할인, 여행자 입력·집계, 음성·문자 흐름 |
| 정용범 — 리더 | 기준·용어 정리와 전체 모델 취합 | 양쪽 흐름·요구 ID 일치 확인. 설명서 담당과 미정 정책 합의 후 전체 그림에 반영 |
